ЧАСТЬ 1. ЭКРАН «УСТРОЙСТВА» (отвязка)
-------------------------------------
1.1. Навигация.
  Профиль → блок «Устройства» (N из M) → кнопка-чип «Управлять» →
  отдельный подэкран «Устройства» (кнопка «Назад» возвращает в профиль).

1.2. Список.
  Каждая карточка устройства: иконка платформы (смартфон/ноутбук),
  имя, платформа + «с <дата>», бейдж «Это устройство» для текущего
  HWID. Карточка ЦЕЛИКОМ — переключатель выбора (не маленькая кнопка!):
  круглая галочка справа; выбранная карточка подсвечивается золотой
  рамкой rgba(230,182,76,0.5) и фоном rgba(230,182,76,0.07).

1.3. Мультивыбор и нижняя панель действий.
  Панель появляется (анимация снизу) когда выбрано >= 1:
    [Снять]  Выбрано: N  (в т.ч. это устройство — если выбрано текущее)  [Отвязать]
  Кнопка «Отвязать» — красная (bg-red-500/90, hover bg-red-500).
  Панель закреплена над нижней навигацией, backdrop-blur, скругление 16.

1.4. Диалог подтверждения (обязателен).
  Заголовок: «Отвязать устройство?» / «Отвязать устройства (N)?»
  Текст: «Имя1», «Имя2» потеряет(ют) доступ к серверу, слот(ы)
  освободится(утся) — на их место можно зарегистрировать другие устройства.
  Если среди выбранных текущее устройство — доп. абзац золотым цветом:
  «Среди выбранных — текущее устройство: после отвязки вы выйдете из
  аккаунта и потребуется заново добавить доступ.»
  Кнопки: «Отмена» (нейтральная) / «Отвязать» (красная).

1.5. Логика отвязки.
  - Последовательно DELETE по каждому выбранному HWID.
  - Успешные удаляются из списка; devicesUsed уменьшается на число успехов.
  - Частичный сбой: тост «Отвязаны не все устройства» + сообщение панели.
  - Полный успех: тост «Отвязано устройств: N» / «Устройство отвязано»,
    «Слот освобождён для нового устройства.», выделение сбрасывается.
  - ТЕКУЩЕЕ устройство отвязывать разрешено: после успешного DELETE
    своего HWID → выход из аккаунта (очистить доступ/сессию) и открыть
    мастер добавления доступа. Текст тоста: «Добавьте доступ заново
    на новом устройстве.»
  - Подсказка внизу списка: «Отвязка освобождает слот: устройство
    потеряет доступ при следующем обновлении ключей. Если отвязать
    текущее устройство — вы выйдете из аккаунта и сможете добавить
    доступ заново (например, на новом телефоне или Mac).»

1.6. Пустые состояния.
  - Нет токена/доступа: «Доступ не добавлен» + кнопка «Добавить доступ».
  - Панель не умеет список устройств: «Панель не поддерживает список
    устройств. Просмотр и отвязка доступны в панели VPNPan. Лимит
    берётся из профиля.»
  - Список пуст: «Пока нет устройств. Устройство появится в списке
    после первого подключения.»
  - Ошибка сети: текст ошибки + кнопка «Повторить».

1.7. API панели (VPNPan), контракт из прототипа:
  - GET  /devices?token=…            → devices[{hwid,name,platform,addedAt}],
                                       devicesUsed, devicesLimit, supported
  - DELETE /devices {token, hwid}    → revoked, devicesUsed
  - POST   /devices {token, hwid, deviceName, platform, action:"register"}
                                     → registered, devicesUsed, devicesLimit
  Регистрация текущего устройства — автоматически при первом
  подключении (HWID генерируется локально и хранится на устройстве).
  Если у панели другие пути/названия полей — маппинг делается в
  слое API-клиента, UX не меняется.

ЧАСТЬ 2. ПОДПИСКА: ПРОДЛЕНИЕ И ОПЛАТА
-------------------------------------
2.1. Профиль, блок «Мой план»:
  - название тарифа, дата окончания;
  - если осталось < 7 дней — жёлтый бейдж «Осталось N дн.», >= 0 и
    истёк — красный «Подписка истекла»;
  - кнопка «Продлить тариф» → шторка продления (bottom sheet).

2.2. Шторка продления:
  - 3 тарифа (выбор одним тапом, выбранный подсвечен золотом):
      1 месяц  — 199 ₽
      6 месяцев — 999 ₽, бейдж «−16%»
      12 месяцев — 1799 ₽, бейдж «−25% · выгодно»
  - подсказка: «Доступ продлевается сразу после оплаты — перезапускать
    приложение не нужно»;
  - кнопка «Оплатить {цена} ₽» → открыть ВНЕШНИМ браузером системы
    URL оплаты: {PAYMENT_URL}?plan=m1|m6|m12
    (QML: Qt.openUrlExternally; не WebView внутри приложения —
    чтобы платёжный 3-D Secure работал без проблем).

2.3. Напоминания об окончании (локально, без сервера):
  - за 7, 3 и 1 день до expiresAt — локальное уведомление/трей:
    «Подписка AIOS закончится через N дн. — продлите тариф в профиле»;
  - в день окончания и после: баннер на главном экране «Подписка
    истекла» с кнопкой «Продлить».

2.4. PAYMENT_URL — сейчас заглушка. Владелец должен сообщить реальный
  адрес платёжной страницы; вынести его в один конфстант
  (аналог src/lib/constants.ts → PAYMENT_URL в прототипе), чтобы
  менять в одном месте.
