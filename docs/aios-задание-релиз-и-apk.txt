ЗАДАНИЕ 1. Опубликовать APK в публичный Release (10 минут работы + ~1 час CI)
--------------------------------------------------------------------

ПРОБЛЕМА: CI собирает APK, но кладёт его в «Artifacts» прогона Actions —
оттуда скачать может только залогиненный в GitHub пользователь. Нужен
публичный Release с постоянной ссылкой на APK.

ЧТО ДЕЛАТЬ (по шагам):

ШАГ 1. Возьми файл aios-build-android-with-release.yml (приложен к этому
заданию / лежит в папке загрузок этого чата). Это ПОЛНЫЙ новый текст
workflow — он заменяет собой текущий файл .github/workflows/build-android.yml
в репозитории. Внутри уже есть всё нужное (сборка Qt 6.10.1 + новый шаг
«Publish APK to public release» в самом конце).

ШАГ 2. В репо Bumer55577/aios-vpn, ветка master, замени СОДЕРЖИМОЕ файла
.github/workflows/build-android.yml содержимым файла из ШАГА 1.
Ничего кроме этого одного файла не меняй. Пример:

    git checkout master && git pull
    cp <путь>/aios-build-android-with-release.yml .github/workflows/build-android.yml
    git add .github/workflows/build-android.yml
    git commit -m "CI: publish APK to public release aios-apk"
    git push origin master

ШАГ 3. Дождись окончания CI: вкладка Actions -> workflow
«AIOS VPN — Android APK» -> самый верхний запуск должен стать зелёным
(займёт ~40–60 минут).

ШАГ 4. Проверь, что появился релиз и в нём APK:
https://github.com/Bumer55577/aios-vpn/releases/tag/aios-apk
В блоке Assets должен лежать файл AIOS-VPN-Android-arm64.apk.

ЕСЛИ ШАГ «Publish APK to public release» ПОКРАСНЕЕТЬСЯ С ОШИБКОЙ 403
(«Resource not accessible» / «Must have admin rights»):
  открой Settings -> Actions -> General -> раздел «Workflow permissions»,
  выбери «Read and write permissions», Save, затем нажми Re-run на прогоне.
  Это разовая настройка репозитория.

ЕСЛИ ПРОГОН ПОКРАСНЕЛ ПО ДРУГОЙ ПРИЧИНЕ: НЕ ПРАВЬ КОД ПРИЛОЖЕНИЯ, не меняй
другие файлы — пришли лог ошибки тому, кто дал задание.
